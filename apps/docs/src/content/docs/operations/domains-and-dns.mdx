---
title: Domains and TLS
description: Connect a domain and satisfy the requirements for Traefik routing and certificates.
---

Codedock manages Traefik for HTTP routing. Application containers receive host-routing and internal-port labels. Your application must listen on the configured port and a container-reachable interface.

## Point DNS at the serving host

Create an A record for your application hostname pointing to the server that serves the application. Add an AAAA record only when IPv6 routing is configured and reachable. For a wildcard application domain, configure its wildcard record explicitly.

```txt
A  app.example.com  YOUR_SERVER_IPV4
A  *.example.com   YOUR_SERVER_IPV4
```

DNS records and a saved domain are separate steps. A hostname stored in Codedock does not establish that public DNS resolves correctly.

## Add the service domain

Add the domain in the application's settings and match its internal port to the application listener. Domain API creation uses `domainName` and optional `pathPrefix` and `redirectTo`. Provider-backed domain creation requires administrator or owner access.

Verify the deployed container, Traefik routing and actual HTTP response after changing the domain. If settings require redeployment to update container labels, redeploy and inspect the resulting labels.

## Automatic certificates

Traefik enables its Let's Encrypt resolver when a TLS email is configured. The current resolver uses the HTTP-01 challenge on the `web` entrypoint, port 80. Certificates are stored in the persistent `codedock-traefik-acme` volume.

Certificate issuance needs all of these:

- The hostname resolves to the correct public host.
- Port 80 is reachable from the internet for the HTTP-01 challenge.
- Traefik owns those listening ports and is running.
- A TLS email and matching resolver are configured.
- The hostname is eligible for a publicly trusted certificate.

Port 443 must be reachable to serve HTTPS after issuance; it is separate from the port-80 HTTP-01 validation requirement.

HTTP-01 does not issue wildcard certificates. A wildcard DNS record can support individual hostnames, but that is different from a wildcard TLS certificate. Localhost and private-only names do not receive public Let's Encrypt certificates through this path.

## Worker hosts

Point an application's DNS at its serving worker, not automatically at the control plane. Verify that the worker has the required proxy, network and certificate configuration. SSH reachability alone does not establish public HTTP routing.

## Troubleshoot

1. Resolve the hostname externally and check for stale A or AAAA records.
2. Confirm firewall rules and that no other process owns ports 80 or 443.
3. Inspect application and Traefik logs.
4. Check the service's listening address and internal port.
5. Check the TLS email, resolver and persistent certificate storage.
